# Plan 600-02: Add pair-scoped flow certification

## Objective

Extend the generated baseline with compact, source/destination pair cells and
flow-aware connector certification without treating individually capable
endpoints as compositional proof.

## Captain clarification — mandatory warehouse-mediated round trips

Every generated flow is a three-stage pipeline, never a direct connector hop:
`source connector -> local Parquet warehouse -> destination connector`. This
applies to all four pair classes, including database source/destination pairs.
The warehouse is a required, explicit mediator in both the generated identity
and the evidence contract. A source and destination may be the same connector:
GitHub-to-GitHub is a legitimate pair and must not be filtered from a product.

`live_tested=true` for a flow means one real `pm` binary ran the complete round
trip and independently read the delivered data back from the destination. It
cannot be inferred from successful individual ETL/reverse-ETL legs. Accepted
flow evidence must cite the complete run, an independent warehouse readback,
and an independent destination readback.

Delivery guarantees are separate from whether that round trip worked. A passed
flow cell carries an explicit delivery contract for `resumable`,
`receipt_backed`, `checkpointed`, `replay_identity`, and
`provider_idempotency_key`; each false guarantee has a named limitation. This
allows a one-shot GitHub reverse leg to be honestly recorded as working while
remaining explicitly non-resumable and receipt-unbacked, rather than advertising
guarantees the implementation does not provide.

## Threat model

| Threat | Boundary | Mitigation | Verification |
|---|---|---|---|
| Endpoint evidence is reused as flow proof | capability records to pair certification | Flow evidence keys both source and destination and requires destination readback | pair evidence validation test |
| Successful ETL/reverse legs are mislabeled as an end-to-end flow | two-leg pipeline to certification | Require a single real-`pm` round-trip record plus warehouse and destination independent readbacks | round-trip evidence validation test |
| A same-connector round trip is silently omitted | pair construction | Preserve source==destination products, including GitHub-to-GitHub | pair resolver test |
| A working one-shot reverse leg is advertised as resumable | evidence contract to report | Serialize each delivery guarantee and named false-guarantee limitation independently of `live_tested` | delivery-contract validation test |
| API sink claims are accepted despite no durable acknowledgement | app flow admission to matrix | Derive implementation from `DurableETLDestination` / warehouse materializer runtime contracts | API destination red-baseline test |
| Non-applicability is hidden by omitted pair data | role facts to matrix consumer | Generate all four endpoint roles for each connector with named reasons; serialize candidate pair products plus exact overrides | role reason and pair resolver tests |
| Output explodes into an unreviewable cartesian product | hundreds of connectors to committed JSON | Encode disjoint source/destination sets with a default pair cell and pair-key overrides; report exact pair counts | deterministic compact rendering test |
| A connector becomes certified while an applicable flow is false | capability and flow aggregation | Require capability completeness and every involved applicable pair cell before final `certified=true` | aggregation test |
</threat_model>
