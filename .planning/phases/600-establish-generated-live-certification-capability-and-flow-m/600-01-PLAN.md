# Plan 600-01: Generate the truthful capability baseline

## Objective

Build the source-derived capability matrix, strict evidence model, regeneration
command, drift check, and committed baseline without fabricating live results.

<threat_model>
## Threat model

| Threat | Boundary | Mitigation | Verification |
|---|---|---|---|
| A filename named `certification.json` promotes a connector | legacy bundle/fixture files to generated state | Scan only the new proof-bearing evidence namespace; report legacy names as ignored inventory | test that only accepted typed evidence is read |
| A new engine kind disappears from certification | executable source to generated artifact | Parse `expectedOperationBlock` and capability structs; byte-level `--check` fails after source changes | source discovery and drift tests |
| A stub is mistaken for code | native connector/runtime boundary | Inspect actual registered implementation and reject direct `ErrUnsupportedOperation` methods; cover PostgreSQL/MySQL | stub regression test |
| A malformed reason suppresses a requirement | artifact/evidence boundary | Require non-generic code plus non-empty explanation for every N/A state | N/A validation test |
| User-controlled path escapes the checkout | generator argument to filesystem | Resolve fixed repo-relative output and accepted evidence paths; reject invalid relative evidence references | path/evidence validation tests |
| A certificate asserts a live run without retained proof | live run to generated artifact | Require embedded sanitized request/response proof before live_tested can become true | proofless evidence rejection test |
| Fixture data, request data, or provider responses leak secrets | test transport to artifact | Redact actual prepared secret values before persistence, then conservatively redact every unproved request/response value including response bodies | sanitizer and unsafe-proof rejection tests |
</threat_model>
