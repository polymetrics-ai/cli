# Summary — issue 4325 declaration-admission foundation

This phase adds a provider-I/O-free declaration-completeness certificate:
`connectorgen declaration-admission`. A required, independently counted source
cohort lists cited provider operations; a separate catalog declares their
canonical lane/endpoint/binding/CLI command and either an existing runtime
binding or a named deferred foundation. It is
deliberately separate from source retention, credential-bound runtime
certification, and live proof. It reuses the real no-I/O command resolver so a
passing admission row cannot drift from runtime preflight semantics.

Deferred commands are explicit `cli_surface.json` records with a typed,
evidenced, exact-target `foundation_gap`; they remain discoverable and
commandrunner rejects them with a typed missing-foundation refusal only after
validating the full source and binding identity. The compact target ledger is
embedded so shipped preflight stays strict without the full API-surface file.
No connector-owned definition is converted in this shared foundation phase.

The R2 repair makes source uniqueness provenance-only, checks binding
uniqueness independently, and replaces endpoint substitution with named
fail-closed canonical/transport equivalence. Commandrunner now tries its real
implemented path before accepting an executor-specific deferred foundation,
and the compact source ledger has one exact production inventory class. A
clean real-bundle census proves 243 REST/binary aliases plus 4 GraphQL aliases;
the real Outreach `/api/v2` ETL and destructive shapes pass the no-I/O
integration gate. This preserves the captain policy that a connector with zero
runnable operations may still earn declaration admission when every source row
is complete, discoverable, explicitly deferred, and names its missing
foundation; it does not confer runtime or live usability.
