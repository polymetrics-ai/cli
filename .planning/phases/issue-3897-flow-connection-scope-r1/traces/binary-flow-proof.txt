# Fresh binary flow source-read proof — 2026-08-11

A fresh pm binary built with go build -o <temporary-root>/pm ./cmd/pm
initialized an isolated project. Two local file connections, acme and globex,
each materialized a distinct JSONL fixture into the same warehouse table name
records:

- acme: {"id":"acme-proof","owner":"acme"}
- globex: {"id":"globex-proof","owner":"globex"}

The binary ran a JSON flow query with connection="acme". Its SQL returns
acme-proof only when the source view contains exactly one acme-proof row; its
other branch raises the DuckDB error "wrong connection selected".

pm flow run --force --json satisfied:

    .status == "ok" and .steps[0].status == "ok"
    true

The same fresh binary then returned and asserted actual warehouse rows, not
only exit status:

    pm query run --table records --connection acme --json
    count=1 rows[0].id=acme-proof rows[0].owner=acme

    pm query run --table records --connection globex --json
    count=1 rows[0].id=globex-proof rows[0].owner=globex

Both JSON predicates evaluated to true. The action path was not invoked; no
provider call or external mutation is part of this proof.
