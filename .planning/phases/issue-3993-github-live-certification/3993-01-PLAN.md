  <behavior>
    The external Node proof runner must never be called one-process,
    in-process-rate-coordinated evidence. Its report records a closed execution
    model that accurately identifies per-operation child processes, and a
    credentialed run is rejected as current certification unless the caller
    supplies the built-in in-process `pm connectors certify` result as its
    separate proof source. Its report schema continues to redact all supplied
    config values and rejects unsafe boundary/case inputs before a child starts.

    Cases:
    - a report with `execution_model: external_pm_per_operation` validates only
      as a historical/diagnostic external-runner measurement, never as a
      `credentialed_live` current certification;
    - a forged `credentialed_live` report that claims the external model fails
      validation without exposing input data;
    - configuration redaction is proven by exact redacted argv structure, not
      by a URL substring assertion that triggers CodeQL.
  </behavior>
  <implementation>
    Add a closed execution-model field to the runner report/validator and
    require the live status to use the actual model rather than a barrier label.
    Keep `single_barrier_release` as launch topology only. Remove the unused
    `buildCases` import and replace the scan-prone URL substring expectation
    with a complete structural redaction assertion. Do not add a generic
    request path, serialize the barrier, alter rate limits, or copy #4059.
  </implementation>
</feature>
