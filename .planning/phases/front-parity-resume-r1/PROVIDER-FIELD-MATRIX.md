# Front provider-field research matrix

This temporary research artifact satisfies the 2026-08-05 per-request-field citation ruling without proposing a production citation schema. It was derived from Front's provider-owned [documentation index](https://dev.frontapp.com/llms.txt) and the embedded **OpenAPI definition** on each referenced page.

## Scope and method

- Provider snapshot: 346 indexed reference pages; 274 pages with parseable embedded OpenAPI; 255 documented operation pages; 254 unique method/path operations. The one duplicate documentation page is `PATCH /channels/{channel_id}`, retained separately in the bundle's duplicate disposition.
- Each matrix row groups only fields that share one provider URL and OpenAPI section. Every listed field still carries its own location and requiredness rationale.
- Tier 1 evidence is provider machine-readable OpenAPI: `parameters` for path/query input and `requestBody.content[...]` schemas for body, form, and file input. Confidence is high because the source is the operation's embedded provider schema.
- A schema property is required only when its immediate parent schema's `required[]` contains it; parameter requiredness comes directly from `parameter.required`.
- Provider array bounds supported by the current engine are enforced in `writes.json`. Provider `minLength` and `maxLength` rules are preserved in `schemas/request_contracts.json`, because `internal/connectors/engine/schema.go` currently rejects those draft-07 keywords as unknown; this connector-owned change does not alter shared validation.
