# TDD ledger — unpushed-work safety net r1

| ID | Contract | Red evidence | Green evidence | Refactor / verification |
|---|---|---|---|---|
| R1 | Default branch, dirty worktree, detached worktree, and active Git operation are never pushed. | `python3 scripts/tests/unpushed-work-safety-net_test.py` failed red (7 failures) because the observer did not exist; its rebase fixture created a real conflicted rebase with two local commits. | Split green runs passed the dirty/detached/default tests plus real multi-commit rebase, merge, cherry-pick, revert, bisect, and squash-merge deferral/recovery. A sibling linked worktree pushed while the rebase worktree remained deferred. | Events identify the refusal and the subsequent recovered push. |
| R2 | An observer never rewrites remote work and does not force-push under any path. | The red integration harness creates divergent remote feature history and asserts its SHA remains unchanged after a scan; it cannot execute until the observer exists. | A real divergent remote stayed unchanged; a pre-push race produced an actual non-fast-forward rejection; an actual between-query remote change emitted `remote_changed`, deferred, and recovered; a PATH-wrapped real Git binary rejects `--force`, `--force=*`, and `+<refspec>` in every observer Git invocation while the normal push still succeeds. | Push construction is exactly `<observed-sha>:refs/heads/<branch>` from the common Git database. |
| R3 | The configured push target is the actual Git precedence result and its live push URL determines the default branch. | The red harness uses distinct fetch/push bare remotes with conflicting default branches plus `branch.<name>.pushRemote`; it reached setup after using Git to seed both remotes. | The observer deferred `feature/target` because its effective **push URL** named it as default, even though the fetch remote named `main`; after changing that target's live default to `main`, recovery pushed only to the push URL and left the fetch remote untouched. Multiple push URLs are refused and recover after configuration is made singular. | Unknown remote/default and changed target/ref state are error events, not success. |
| R4 | A killed/busy observer cannot silently suppress later attempts. | The red harness holds a real `fcntl` lock in another process, then expects a visible busy result and post-exit recovery. | The lock test reported `observer_busy` with exit 75, released the holder, and then pushed. A corrupt durable state and a stale heartbeat both report nonzero, then recover on a healthy run. | The lock is kernel-released rather than a timestamp lease; state writes are atomic and failures stop the push visibly. |
| R5 | The ten-minute intent bounds automatic CI trigger attempts. | The red harness commits twice and expects the second scan to report a persisted rate-limit rather than push. | The first feature commit pushed; the second immediate commit reported `rate_limited` and left the remote at the first SHA. `enable --interval-seconds 599` is refused and the generated launchd plist contains `<integer>600</integer>`. | Attempt timestamps are written and fsynced before a push attempt. |
