# Plan — reverse-ETL API-surface derivation r1

## Goal

Make every implemented command that already declares a parseable `METHOD /path` summary expose that endpoint through `api_surface`, independent of intent, and make the omission impossible to reintroduce silently.

## Scope and ownership

- Production ownership: `cmd/connectorgen/surfacesync.go` and its tests.
- Generated ownership: connector CLI surfaces, GitHub's certification sweep, generated CLI docs/website data/skills only when their respective generators report a derived change.
- Target connector for measured recovery: GitHub.
- Exclusions: connector-specific source branches, alias-to-endpoint guesses, status reclassification, credentials, and reverse-ETL execution.

## TDD slices

1. **Red — generic invariant:** Add an all-bundle test that enumerates implemented commands and fails for a parseable endpoint summary paired with an empty `api_surface`. Run it against the base condition; it must report 214 GitHub failures and no aliases.
2. **Red — focused derivation:** Add a minimal reverse-ETL fixture with an address summary and no API surface, plus an alias-like human summary. The first case must remain unsynchronized before the implementation; the second must stay without an API surface.
3. **Green:** Refactor surface synchronization so endpoint-summary derivation runs before any intent filter, parses a connector-relative address with an optional write-action annotation, and fills/corrects the single reference. Preserve operation-derived behavior and all intent-specific policy/flag derivation.
4. **Generated evidence:** Run `surface-sync`, then regenerate GitHub's certification sweep. Count exactly 214 recovered endpoint references, exactly 14 untouched aliases, and compare status buckets before/after; every status delta must be zero unless independently explained.
5. **Determinism:** Run the surface and applicable documentation/data/skills generators a second time. The second pass must leave generated bytes unchanged.
6. **Verification and review:** Run changed-package and consumer tests including `./cmd/connectorgen`, repository gates individually, `verify-work`, and a code review. Record exact results and review dispositions.

## Required skills

`golang-how-to`, `golang-cli`, `golang-testing`, `golang-error-handling`, `golang-design-patterns`, `golang-structs-interfaces`, `golang-security`, and `golang-safety` were loaded. The change is a deterministic metadata transformation: safe parsing, error propagation, and testable generic derivation are the relevant applications.

## CLI help/docs/website parity

- Runtime help and command behavior: not changed; `api_surface` is routing/certification metadata.
- CLI manual prose and website prose: no authored documentation changes expected.
- Generated documentation/data/skills: run their generators and preserve any source-derived metadata updates; confirm second-pass byte stability.
- Bare namespaces and credentialed reverse-ETL execution: not applicable and will not be exercised.
