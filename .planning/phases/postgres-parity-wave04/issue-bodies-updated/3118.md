## Captain policy addendum: destructive/delete operation scope

Destructive operations, DELETE operations, TRUNCATE, and other database-state mutations are included in PostgreSQL parity scope when they are implemented as typed reverse-ETL destructive actions with `confirm: "destructive"` and the existing plan → preview → explicit approval → execute safety path. They must not be blanket-excluded as unsafe solely because they delete, truncate, or otherwise mutate database state. Raw generic SQL write/read/query text remains disallowed.
