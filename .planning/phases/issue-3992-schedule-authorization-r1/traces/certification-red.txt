# Certification compatibility red run

The full CLI certification initially failed after schedule creation began
requiring an authorization reference:

```text
schedule_create: kind got="Error" want="Schedule", exit got=2 want=0
argv: pm schedule create ... --flow cert_flow_sample_events --json
```

The legacy non-action schedule round-trip omitted the required safe reference.
It was updated to pass a fixed opaque `auth_<id>` reference, and the real
sample certification then passed. The actual authorized firing proof remains
the isolated connector-backed `TestInstalledScheduleFireRunsAuthorizedRoundTripAndRestoresBackend`.
