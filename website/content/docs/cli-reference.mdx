This page is the public website contract for the `pm` CLI. When a command is added to the Go dispatcher, `pm docs validate` requires the command to appear here, in the embedded manual, and in `docs/cli`.

## Global contract

| Surface | Contract |
|---|---|
| `pm --help` | Prints the root manual. |
| `pm help <topic>` | Prints the embedded manual for a command group. |
| `pm <command> --help` | Prints that command group's embedded manual. |
| `--json` | Emits a structured envelope for commands that support machine output. |
| `--root <path>` | Selects the project root containing `.polymetrics`. |

<Callout type="info">
  `--json` is the agent path for operational commands. A few developer-facing commands, such as `pm help`, are intentionally plain text because they return human manuals.
</Callout>

## Configuration

`pm` resolves typed invocation configuration once per run from a bounded allowlist. Precedence is:

1. Bound global flags (`--root`, `--json`).
2. Explicit `POLYMETRICS_*` environment variables.
3. Documented `PM_*` legacy aliases when the primary variable is absent.
4. `<project-root>/.polymetrics/config.yaml`.
5. Built-in defaults.

Missing config files are allowed. Malformed YAML is a validation error (exit `3`). The `root` key in a file does not relocate config discovery for the same invocation; use `--root`, `POLYMETRICS_ROOT`, or `PM_ROOT` before loading another project. For malformed files, `--json`, `POLYMETRICS_JSON=true`, or `PM_JSON=true` selects the same single JSON `Error` envelope on stdout used by other validation errors.

Root and `json` affect invocation bootstrap. Runtime, RLM, and schedule keys are consumed by migrated runtime, worker, agent image, schedule, and RLM non-secret call sites. Worker/RLM agent Temporal execution remains opt-in: `runtime.temporal_addr` must be explicitly set by env or config file for those paths, while runtime doctor keeps local Compose defaults.

| Config key | Default | Primary env | Legacy alias |
|---|---|---|---|
| `root` | invocation root (`.`) | `POLYMETRICS_ROOT` | `PM_ROOT` |
| `json` | `false` | `POLYMETRICS_JSON` | `PM_JSON` |

| `project` | `polymetrics-local` | `POLYMETRICS_PROJECT` | `PM_PROJECT` |

  connector: warehouse
  path: .polymetrics/warehouse

<Callout type="warning">
  Configuration is not a secret store. User-named credential variables passed to `--from-env`, connector certification credsfile entries, `PM_LLM_API_KEY`, and provider-specific API key variables stay environment-only. Do not put secret values in `config.yaml`, docs, issues, or chat.
</Callout>

## Connector command surfaces

Connector command surfaces use dynamic `pm <connector> ...` command trees generated from connector
metadata. `pm <connector>`, `pm <connector> --help`, and `pm help <connector>` render a root
manual; a declared group or command followed by `--help` renders its own manual. An unrecognized
connector path is a usage error even when `--help` is present (exit `2`; with `--json`,
`error.code` is `usage_error`). Declared product-safe command paths dispatch through the connector
command runner. See
[/docs/github-cli-surface](/docs/github-cli-surface) for the current command metadata, safety labels,
and safety boundaries.

## Workspace commands

### `pm init`

```bash
pm init --root ./demo --json
```

Creates `.polymetrics/` under the selected root. The workspace stores state, encrypted credential references, local warehouse files, outbox files, catalogs, runs, reverse plans, flow checkpoints, and schedules.

### `pm credentials`

```bash
pm credentials add github-local \
  --connector github \
  --provider-family provider-family \
  --auth-profile service-profile \
  --config owner=OWNER \
  --config repo=REPO \
  --from-env token=GITHUB_TOKEN \
  --json

# Explicitly join a compatible credential as it is created.
pm credentials add provider-secondary \
  --connector github \
  --provider-family provider-family \
  --auth-profile service-profile \
  --link-credential github-local \
  --json

# Or link an existing compatible credential after creation.
pm credentials add provider-existing \
  --connector github \
  --provider-family provider-family \
  --auth-profile service-profile
pm credentials link provider-existing --to github-local --json

pm credentials list --json
pm credentials inspect github-local --json
pm credentials test github-local --json
pm credentials remove github-local
```

Secrets must come from environment variables or stdin. Do not pass raw token values in chat, shell history, or docs.

When omitted, `--provider-family` defaults to the connector name and
`--auth-profile` defaults to `default`. Existing credentials receive the same
defaults when their project is opened. Each credential is isolated unless it is
explicitly linked. A link requires matching effective declarations. For a
cross-connector link, every credential in the resulting cohort must have both
declarations supplied explicitly; matching defaults alone are not enough.

Links only create protected local binding metadata. Credential inspection and
JSON output expose the non-secret family/profile declarations but never the
binding itself; internal coordination receives opaque projections only. This
identity-only release does not change connector authentication, rate limiting,
or transport behavior.

Before saving a credential, `pm` checks non-secret `--config` fields against
only the selected connector's declared string `enum`, `pattern`, and `uri`,
`date`, or `date-time` format constraints. It does not add required, type,
default, unknown-field, or bounds policy. Errors identify the field and
violated constraint without echoing the supplied value.

### `pm connections`

```bash
pm connections create github_to_warehouse \
  --source github:github-local \
  --destination warehouse:warehouse-local \
  --stream pull_requests \
  --primary-key node_id \
  --cursor updated_at \
  --sync-mode incremental_append \
  --table github_pull_requests \
  --json

pm connections list --json
```

Connections bind credentials, a stream, table, sync mode, cursor, and primary key. Add
`--transform-file plan.json` to create an eligible typed database transport with a
closed `TransformPlanV1`; the file is catalog-validated and persisted only as
normalized JSON plus its hash. It supports typed projection/rename, timestamp/date,
checked integer multiply/cast, uppercase, modulo, and a `not_equal` filter—never
arbitrary SQL.

An immutable transformed PostgreSQL full-overwrite target additionally accepts
`--target-copy-workers <n>`. It defaults to `2` and is bounded by `min(8,
target-declared pool maximum)`; the saved policy appears in the closed target
plan and preview rather than becoming an unconstrained ETL run flag.

Connection names accept letters, digits, `-` and `_`, must start with a letter or digit, and must
differ by more than letter case. Ambiguous names are rejected at creation rather than rewritten,
because two connections that cannot be told apart cannot own separate warehouse data. The name is a
display value only — the warehouse keys its directories on a generated identifier.

Against the local warehouse destination, `--stream` and `--table` become path components, so each
accepts only letters, digits, `.`, `-` and `_`. Both are checked when the connection is created,
because a name the warehouse cannot materialize would otherwise fail every sync of that connection.
The [connection manual](https://github.com/polymetrics-ai/cli/blob/main/docs/cli/connections.md)
owns the local-warehouse destination-table rule and recovery for invalid legacy
inventories.

### `pm catalog`

```bash
pm catalog refresh --connection github_to_warehouse --json
pm catalog show --connection github_to_warehouse --json
```

Catalog commands discover and cache stream metadata. Catalog output includes schemas and stream names, never decrypted secret values.

## Connector discovery

```bash
pm connectors list --json
pm connectors list --all --json
pm connectors catalog --capability read --json
pm connectors catalog --stage generally_available --json
pm connectors port-plan --all --json
pm connectors port-plan postgres --json
pm connectors inspect 100ms --json
pm connectors help 100ms
pm connectors certify sample --full --json
```

`pm connectors list` shows bundle-backed connectors. `pm connectors list --all` and `pm connectors catalog` expose the generated connector catalog with capability metadata, streams, write actions, and schema information.

`pm connectors inspect <name>` also shows the generated certification quality
signal: either **CERTIFIED** or **COMMUNITY BUILD, UNCERTIFIED**. The latter is
a visible warning, not an availability gate; users can still run the connector.
Certification is based on proof-bearing live records, not whether a command is
reachable or a legacy certification filename exists.

For connectors with a declared rate-limit policy, inspection reports rate-limit coordination
provenance. `process_local` protects requests inside the current `pm` process only; it is not a
cross-process claim. A policy explicitly declared `require_shared` refuses before sending a request
if its optional shared coordinator is unavailable. A connector with both ordinary policies reports
`mixed` policy-scoped provenance. A certification-only `require_shared` overlay preserves the
`process_local` default label and explicitly states the certification boundary. Neither human nor JSON
inspection exposes a scope, coordinator address, or credential.

From a source checkout, `pm connectors certify <connector> --full --json` runs the legacy test
harness and includes an API-surface
inventory. Its `capabilities.surface.provenance` block reports provider-artifact evidence separately
from endpoint coverage and connector capabilities: ledger version, artifact count, endpoint count,
cited endpoint count, and a status. Existing version-1 and pre-ledger inventories report
`legacy_unverified` during the staged migration; invalid version-2 provenance fails certification.
Provenance never supplies a `covered_by` binding, enables a command, or sets
the generated certification quality signal.

For a full-fidelity live HTTPS proof, add `--external-proof --full-parity` and
supply credentials only with `--from-env` or `--value-stdin`. This
source-checkout mode builds a fresh `pm` child binary, keeps the
credential session in memory, and writes only salted fingerprints of the
observed process transcript and complete bounded exchanges. It refuses an
incomplete or truncated exchange before creating a proof artifact.

```bash
pm connectors certify github --external-proof --full-parity \
  --config owner=OWNER --config repo=REPO --from-env token=GITHUB_TOKEN --json
```

For connectors with coordinated provider budgets, the JSON report may include
`rate_limit_events`. These report safe attempt, wait, reset, and not-sent
outcomes so a stopped request is distinguishable from a provider response. They
never include credentials, rendered requests, or rate-scope subjects.

## Extract, query, and write

```bash
pm etl check --connector github --config owner=OWNER --config repo=REPO --config public_access=true --json
pm etl catalog --connector github --config owner=OWNER --config repo=REPO --config public_access=true --json
pm etl read --connector github --stream issues --limit 10 --config owner=OWNER --config repo=REPO --config public_access=true --json
pm etl run --connection github_to_warehouse --stream pull_requests --batch-size 500 --json
pm etl status <run-id> --json
```

Use direct `check`, `catalog`, and `read` while developing a connector or testing credentials. Use `pm etl run` for configured syncs.

```bash
pm query run --table github_pull_requests --limit 20 --json
pm query run --sql "SELECT * FROM github_pull_requests LIMIT 20" --json
pm query run --table github_pull_requests --fields id,title,state --agent-mode summary --sample 3
pm query run --table github_pull_requests --fields id,title,state --agent-mode stream
```

Queries run on embedded DuckDB over the warehouse's Parquet tables, so read-only `SELECT` and `WITH` statements are supported in full. Agent mode adds compact summary JSON and projected NDJSON output for token-sensitive callers.

```bash
pm reverse list --json
pm reverse plan prs_to_github --source-table github_pr_candidates --destination github:github-local --action create_pull_request --map title:title --map head:head --map base:base --json
pm reverse preview <plan-id> --json
pm reverse run <plan-id> --approval-token-stdin --json
pm reverse status <run-id> --json
```

Reverse ETL is always plan, preview, approval, run. JSON plan output omits the approval token.

## Agent and automation commands

```bash
pm agent plan --request "sync sample customers" --json
pm extract --request "show active customers" --sql "SELECT * FROM customers LIMIT 20" --json
pm skills generate --dir docs/skills --json
```

`pm agent plan` returns typed command suggestions. `pm extract` classifies natural-language requests and routes simple requests to query or RLM analysis. `pm skills generate` writes agent skill files from the command and connector metadata.

```bash
pm agent image build --json
pm agent image pull --json
pm agent image ensure --json
pm rlm run --spec spec.json --in customers --out scored_customers --mode deterministic --json
pm worker status --json
pm worker serve --json
```

RLM agent mode is optional and runtime-backed. It uses Temporal plus a Podman-managed agent image; it is not part of the dependency-free quickstart.

```bash
pm flow create --file flow.json --json
pm flow plan --file flow.json --json
pm flow preview --file flow.json --json
pm flow run nightly_leads --force --json
pm flow status nightly_leads --flows-dir .polymetrics/flows --json
pm flow list --flows-dir .polymetrics/flows --json

pm schedule create --name nightly --cron "0 2 * * *" --flow nightly_leads --json
pm schedule list --json
pm schedule inspect nightly --json
pm schedule status nightly --json
pm schedule install nightly --crontab --json
pm schedule fire nightly --json
pm schedule remove nightly --crontab --json
```

Approve each reverse-ETL job once at connection, schema, preview, mapping,
destination-action, credential-revision, and confirmation-policy granularity.
`pm flow create` then composes existing ETL connections and approved reverse-ETL
jobs; missing, malformed, unrecognised, or unapproved references are refused
before a flow file is written. RLM flow steps reuse the same analyzers as
`pm rlm run` and resolve relative `spec` paths from the flow manifest file.

Schedules accept only an existing valid flow. The installed crontab payload is
exactly `pm --root <root> flow run <name> --json`: it contains no approval token
or authorization reference. Each unattended firing reloads the jobs and
revalidates credential revision, manifest/schema, source scope, mappings,
destination action, confirmation policy, expiry, and revocation. Drift and
failed, ambiguous, rate-limited, or cleanup-failed writes park or halt without
automatic replay. `inspect` and `status` show only terminal status, prepared
execution identities, and opaque receipt IDs.

The [`pm flow` CLI manual](https://github.com/polymetrics-ai/cli/blob/main/docs/cli/flow.md)
owns job references and flow source selection. An action derives its standing
authorization and executable scope from the referenced approved job; flow and
schedule commands do not accept an authorization carrier. Typed connector
validation/write, target read-back, a prepared-execution identity, and a
persisted receipt all precede a successful checkpoint.

## Operational commands

```bash
pm runtime doctor --json
pm perf compare --iterations 25 --json
pm perf compare --iterations 25 --runtime --json
pm perf sync-modes --records 1000 --json
```

Runtime-backed checks require PostgreSQL, DragonflyDB, and Temporal. The dependency-free path is the default. `pm perf sync-modes` excludes typed compatibility names that refuse before source I/O.

```bash
pm docs generate --dir docs/cli --connectors-dir docs/connectors
pm docs validate --dir docs/cli --connectors-dir docs/connectors --website-dir website/content/docs
```

`pm docs validate` is a release gate. It fails when a public command or subcommand is missing from embedded help, checked-in CLI markdown, website MDX, or connector docs.

## Exit codes

| Code | Category | Use |
|---:|---|---|
| `0` | success | Continue. |
| `2` | usage | Fix command shape. |
| `3` | validation | Fix argument values. |
| `4` | auth | Add or rotate credentials. |
| `5` | connector | Inspect connector-specific failure. |
| `6` | runtime | Start required runtime service. |
| `7` | policy | Obtain approval or satisfy policy. |
| `1` | internal | Treat as a bug. |
