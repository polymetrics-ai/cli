The GitHub connector now has a JSON-first command surface contract at
`internal/connectors/defs/github/cli_surface.json`. It uses the current
[GitHub CLI manual](https://cli.github.com/manual/gh), the
[GitHub CLI full reference](https://cli.github.com/manual/gh_help_reference), the
[GitHub REST API docs](https://docs.github.com/en/rest), and the
[GitHub GraphQL docs](https://docs.github.com/en/graphql) as source material.

This is metadata plus a guarded runtime path. It tells `pm` and docs renderers which GitHub commands
are ETL reads, which create approval-gated write plans through fixed REST or GraphQL operations, and
which local workflow features stay outside connector API dispatch.

The generated counts below are current source-inventory evidence, not connector certification. The
historical GitHub gap-map counts are archived as actively wrong because they were measured on the
wrong branch; see the [connector delivery canon](connector-delivery).

## Interpreting the generated surface

The table above is generated from the connector bundle and source lock; it owns counts and current
availability. Inspect a path with `pm github <path> --help` before use—the command's declared
contract, not its family name, determines what the binary can dispatch.

| Family | Runtime boundary |
|---|---|
| Stream and direct reads | Typed reads use declared stream or operation contracts and connector-scoped authentication. |
| Reverse ETL and direct writes | Fixed writes create plans and follow preview, approval, and execution gates. |
| Typed GraphQL | Query and mutation operations use the fixed GitHub GraphQL transport; no generic GraphQL escape hatch is exposed. |
| Unsupported entries | API and local-workflow entries remain declared for discoverability but are not executable. |

## Runtime write flow

Mapped command writes never mutate GitHub directly from a plain invocation. A provider-style command
creates a stored reverse plan. Non-destructive plans return an approval token in text output;
destructive plans return it only after their no-network preview succeeds and additionally require
`--confirm destructive`. JSON output omits the approval token. See the
[Reverse ETL security model](/docs/reverse-etl) for the authoritative lifecycle and
connector-command record handling.

```bash
pm github issue close --issue-number 101 --credential github-token
pm github issue close --plan <plan-id> --preview --json
pm github issue close --plan <plan-id> --approval-token-stdin --json
```

Each command needs its own declared input contract; there is no generic raw-input fallback. Sensitive
writes are available only where their declaration supplies the required input, redaction, scope, and
approval controls.

## Deliberate limits

The connector does not expose generic shell, unrestricted HTTP write, unrestricted SQL write, raw
GraphQL mutation, or `gh api`-style escape hatches. Any future command must remain connector-scoped,
typed, and subject to the same authentication, validation, approval, and redaction boundaries as the
generated entries.
