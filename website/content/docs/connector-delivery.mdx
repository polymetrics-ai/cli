---
title: source.lock vNext connector delivery
description: One immutable authoring input, deterministic execution JSON, and executable lane proof.
---

Connector authors use one pipeline:

```text
source.lock.json -> canonical operation descriptors -> closed published execution generation
```

The schema-4 lock is immutable authoring/evidence input. `connectorgen
lock-render` stages a complete connector-local generation, semantically
revalidates it, fsyncs it, and atomically selects it through `CURRENT`.
`lock-render --check` verifies that selected generation without writing.
Runtime remains execution-JSON-only; this authoring checkpoint neither
materializes the checked-in corpus nor adds a runtime `CURRENT` reader.

Every connector explicitly declares seven lanes: direct read, direct write,
binary download, binary upload, ETL, reverse ETL, and sync transport. One
provider operation may back several lanes, but interactive and saved semantics
remain distinct.

Saved movement always crosses DuckDB:

```text
API      -> DuckDB -> API
API      -> DuckDB -> database
database -> DuckDB -> API
database -> DuckDB -> database
```

Before delivery, prove deterministic closed-generation publication,
execution-only discovery, malformed-artifact rejection, unambiguous command
bindings, real encoders and executors, fake-server wire behavior, and DuckDB
saved flows. Publication proof includes fault recovery, reader/writer
whole-generation visibility, and lease-safe pruning.

```bash
make connectorgen-vnext-locks
make connector-runtime-preflight
make connector-canon-check
```

Provider evidence and external operational tests never become runtime state. A
genuine missing shared encoder or executor is reported through the Foundation
Atlas before new runtime work begins.
