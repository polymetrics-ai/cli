---
title: Reverse ETL
description: Write data back to any destination using the plan-preview-approve-run gate that keeps humans and agents in control.
---

Reverse ETL in pm follows a strict four-step gate: **plan, preview, approve, run**. Destructive operations cannot receive an approval token until their no-network preview is persisted, and no connector action executes until an approval token is explicitly presented at run time.

## The four-step gate

```bash
pm reverse plan <name> [flags]                       # generate a typed plan
pm reverse preview <plan-id>                         # inspect; destructive plans issue their token here
pm reverse run <plan-id> --approve <token> [--confirm destructive] [--json]
```

<Callout type="warn">
  The command group is `pm reverse`, not `pm reverse-etl`. There is no `pm reverse-etl` command.
</Callout>

## Step-by-step walkthrough

### 1. Create a plan

```bash
pm reverse plan sync \
  --source-table open_issues \
  --destination github:my-github \
  --action create_issue \
  --map title:title \
  --map body:body \
  --json
```

The `plan` subcommand reads from the named table, maps columns to action fields, and returns a plan ID. Non-destructive plans also return an approval token in plain-text mode. Destructive plans deliberately do not: their token is issued only after preview succeeds. Newly created plans persist the destination write action's `redact_fields` metadata and mask those fields in plan samples.

JSON output:

```json
{
  "api_version": "polymetrics.ai/v1",
  "kind": "ReversePlan",
  "plan": {
    "id": "plan_abc123",
    "name": "sync",
    "status": "pending",
    "record_count": 5,
    "expires_at": "2026-01-15T11:00:00Z"
  },
  "approval_required": true
}
```

<Callout type="info">
  Approval tokens are printed only in plain-text mode and are **omitted from JSON output**. For destructive plans, run preview without `--json` to receive the token after inspecting the output. Tokens are time-bounded and single-use.
</Callout>

### 2. Preview the plan

```bash
pm reverse preview plan_abc123          # destructive plans issue the token here
pm reverse preview plan_abc123 --json   # machine-readable output redacts the token
```

Preview returns the plan metadata and mapped sample rows. For destructive plans it also runs the destination's real no-network dry-run path, returns resolved warnings, persists a digest of the staged request, changes the plan status to `previewed`, and issues the approval token in plain-text output. Plans created with persisted connector-declared `redact_fields` keep those fields masked.

```json
{
  "kind": "ReversePlanPreview",
  "plan": {
    "id": "plan_abc123",
    "status": "planned",
    "record_count": 5,
    "actions": [
      { "action": "create_issue", "title": "Fix login bug", "body": "Steps to reproduce..." }
    ]
  }
}
```

### 3. Execute with an approval token

```bash
pm reverse run plan_abc123 --approve tk_xyz789 --json
# Destructive plans additionally require: --confirm destructive
```

JSON output:

```json
{
  "api_version": "polymetrics.ai/v1",
  "kind": "ReverseRun",
  "run": {
    "id": "run_def456",
    "status": "completed",
    "plan_id": "plan_abc123",
    "records_succeeded": 5,
    "records_failed": 0
  }
}
```

## Listing plans and runs

```bash
pm reverse list --json
```

Returns all plans and their associated runs.

## Security model

| Guarantee | Detail |
|---|---|
| **Approval tokens are time-bounded** | A token expires after a configurable window. Expired tokens are rejected. |
| **Tokens are single-use** | Replaying a token returns exit code `7` (policy / approval needed). |
| **Destructive tokens follow preview** | DELETE and declared destructive operations receive no token until a no-network preview digest is persisted. |
| **Preview identity is revalidated** | The app recomputes the digest immediately before dispatch; the shared engine gate compares it again. |
| **Confirmation is closed and typed** | Destructive execution accepts `--confirm destructive`, not caller-defined confirmation text. |
| **Secrets are never printed** | Only secret field names appear in plan manifests; newly created plans with persisted `redact_fields` mask connector-declared sensitive sample fields. |
| **Agents get a diff first** | An agent can run `plan` and `preview` autonomously; it must present an approval token for `run`. |

This design lets you delegate reverse-ETL to an AI agent with confidence: the agent proposes changes, a human (or an explicitly trusted policy) issues the token, and only then does data move.

## Exit codes

| Code | Meaning | Recommended action |
|---:|---|---|
| `0` | Success | Continue. |
| `4` | Auth error | Surface to a human to update credentials. |
| `7` | Approval required | Obtain an approval token from the plan step, then retry. |
| `1` | Internal error | File a bug report. |
