# Request-contract outbound-value coverage

Measured on 2026-08-05 against the connector definitions in this worktree. Enforcement is intentionally fail-closed while the coverage manifest remains incomplete.

| Outbound mechanism | Citation coverage | Enforcement layer | Enforcement and focused evidence |
| --- | --- | --- | --- |
| Operation dispatch kind and method | Covered | Shared engine direct-read eligibility predicate, operation-contract provider, command preflight, command runtime | Preflight resolves the referenced operation through the same engine-owned eligibility predicate used by runtime, including the `rest_read` or `provider_search` kind, provider-search POST restriction, relative endpoint, request-body shape, response bound, and tracked API surface. It then rejects method drift from `api_surface`. A `rest_write` operation or stale `GET` surface marker therefore cannot pass preflight as a direct read. |
| REST path variables | Covered | Shared loader parser, connector authoring validator, command runtime | The shared path-template parser derives every `/path/<token>` field; the loader requires a citation and every operation-backed command requires a pointer-addressed flag. `TestBundleLoadValidatesFullRESTPathParameterGrammar` covers the four HubSpot `{subscription-id}` shapes recorded in the manifest. |
| REST query | Covered | Shared query-name validator, loader, connector authoring validator, command runtime | `rest.query`, every `required_query.any_of` name, and write-action query keys derive `/query/<token>` fields. Plain names and explicitly balanced non-empty bracket segments such as `filter[status]` share one safety grammar at authoring and runtime; malformed brackets, query delimiters, whitespace, and controls are rejected. |
| REST required query | Covered | Loader and connector authoring validator | Every alternative name is included in the derived field set before citation and flag validation. `TestBundleLoadRequiresRequiredQueryCitations` covers the fail-closed path. |
| Static REST body | Covered | Shared schema compiler, connector authoring validator, engine runtime schema validator | Every nested static value derives an escaped JSON Pointer. Every supplied static array element is validated against the complete compiled item schema, including value types and nested requirements, before static fields may satisfy required mappings. |
| Body-schema properties | Covered when closed | Shared schema compiler and CLI-emission model, loader, connector authoring validator, command preflight, command runtime | Every property and array item is derived recursively as an escaped JSON Pointer. Operation-backed `maps_to` uses decoded pointer tokens end to end, so literal `a.b` remains distinct from nested `a` then `b`; `/` and `~` use `~1` and `~0`. Preflight requires the connector's operation body contract for every POST, including commands with zero body flags, and validates its static body plus required and optional assignments. Every supported CLI output domain and each `string_array` item domain is checked against normalized schema constraints using actual CLI emission semantics: required inputs exclude blank strings and imply at least one array item, scalar formats constrain candidates, every runtime-emittable value in a finite CLI enum must validate against the complete compiled schema node, and non-enum pattern compatibility is evaluated as one compiled-language product across every effective `allOf` pattern, trimming, scalar format, comma tokenization, and runtime control-character and dangerous-Unicode rejection. The date-time language conservatively includes both one- and two-digit hours accepted by Go's RFC3339 layout parser. Empty intersections are rejected; a bounded or indeterminate product remains supported rather than inventing an incompatibility. The runtime and validator also share comma splitting, trimming, and empty-token removal for string arrays. Thus an integer flag cannot satisfy a number enum containing only `1.5`; a required string cannot satisfy an empty-string-only enum, `pattern: ^$`, or a whitespace-only pattern; a date-time flag cannot satisfy `pattern: ^open$`; mutually exclusive `allOf` patterns cannot pass independently; a string-array item cannot satisfy an empty-only or delimiter-requiring pattern; a required string array cannot satisfy `maxItems: 0`; and unsafe or unsplittable array items cannot prove compatibility. CLI/schema array-cardinality ranges must have a non-empty intersection. Runtime assembly consults that same schema, preserving numeric object keys while treating numeric tokens under arrays as indices; array indices sort numerically. An object node must declare `additionalProperties: false`; 125 existing REST operations contain a directly discoverable open object and are rejected. |
| CLI request assignments | Covered | Shared pointer-assignment validator, connector authoring validator, command preflight, command runtime | Exact duplicate path, query, and body targets are rejected, as are body parent-child targets that would overwrite one another. Concrete array pointers are assembled independently for the required set and every optional input, so sparse indices fail before a command is declared executable; canonical `/0` pointers remain evidence keys only. |
| Static and flag body merge | Covered | Shared engine merge semantics, connector authoring validator, command preflight, engine operation direct-read runtime | Static and dynamic objects deep-merge recursively before final body-schema validation. Nested overrides replace their target while preserving static siblings; object-valued overrides replace non-object values, and arrays replace wholesale. Authoring and Preflight validate the effective required body and every optional override using this exact merge function, including replacement of a static scalar by a flag-built object, loss of static array siblings after an array override, and required static-only POST bodies with zero flags. `TestOperationReadBodyDeepMergesStaticAndFlagObjects` exercises the acting layer. |
| `allOf` composition | Covered | Shared schema compiler consumed by loader and CLI validation | Loader citation derivation unions compatible branches. Incompatible closed-object property sets and genuinely empty type intersections are rejected; `number` intersected with `integer` normalizes to `integer`. `TestSchemaMappingRequirementsUseCompiledComposition` covers these semantics. |
| `anyOf` / `oneOf` composition | Rejected for operation-backed CLI commands | Shared schema compiler and connector authoring validator | Runtime can validate alternatives, but current CLI metadata cannot express alternative or exclusive required-flag groups. The compiled-schema helper returns an explicit error instead of omitting branch requirements. This subsumes the safety scope of queued `cli-schema-deriver-union-arms-r1`; supporting those commands still needs a new CLI constraint representation. |
| `additionalProperties` | Rejected unless closed | Loader request-field enumeration | Missing, `true`, and typed open-object forms are rejected recursively. Typed write `dynamic_fields` is separately rejected from request-contract claims until the operation-side contract has an equivalent typed wildcard representation. |
| `body_field` extraction | Covered as wire shape | Loader cross-file write-link validator | `json_array` requires an exclusively array-rooted compiled schema and cites the outgoing element as `/body/0` plus descendants; the source record's `body_field` name is not falsely treated as a wire property. `TestRequestContractFieldsModelRootArrays` covers this mapping. |
| Root arrays | Covered for write promotion; rejected for operation-backed direct reads | Loader and connector authoring validator | Root-array elements use `/body/0`; object element properties use `/body/0/<field>`. Primitive elements still require the element citation. An object or mixed array/null root is rejected for `json_array`. Direct-read CLI assembly is map-shaped, so those commands fail closed. |
| Multipart parts | Covered | Loader cross-file write-link validator | Every outgoing part name derives a `/body/<part-name>` input independent of its record source field. Surrounding whitespace is rejected rather than trimmed away from the runtime wire name. `TestDeclaredWriteRequestFieldsCoverWireMechanisms` covers field and file parts. |
| Base64 upload fields | Covered with one fail-closed restriction | Loader cross-file write-link validator | The local/source field is excluded, the encoded content field and ordinary JSON fields require citations, and linked actions with query parameters are rejected because the current runtime does not transmit that query. |
| `dynamic_fields` | Rejected | Loader cross-file write-link validator | Dynamic keys are typed and bounded in writes metadata but cannot yet carry operation-side per-key citations. A request-contract claim therefore fails instead of treating the container citation as evidence for arbitrary child keys. |
| GraphQL variables | Covered | Loader cross-file write-link validator | Fixed variable names and nested values derive `/body/variables/...` pointers. Objects containing `template` are scalar variable descriptors, matching `resolveGraphQLValue`, so descriptor metadata never becomes a wire field. Fixed document and operation name remain definition metadata. |
| Write-field evidence mapping | Covered when one-to-one | Loader cross-file write-link validator | Distinct path, query, and body inputs must map injectively to cited request fields. No path aliases are inferred; an alternative may exist only when a future explicit representation proves one template slot. `TestWriteRequestContractMappingsAreInjective` covers body and query evidence aliasing. |
| Write hooks | Rejected by effective ownership | Loader querying the effective runtime dispatch registry | 106 actions are actually hook-handled: all 98 Ashby writes and 8 GitHub actions. Validation queries the dispatch owner used by runtime, not optional action metadata. `TestBundleLoadRejectsEffectiveWriteDispatchRequestContractClaims` covers both false-positive marker metadata and an unmarked effective owner. |
| Explicit empty body | Covered | Loader and connector authoring validator | A REST operation with neither a non-empty static body nor a body schema must declare `body: "none"`; `{}` and omission fail loading. Path and query citations still require command flags. |

The coverage counts above measure only shapes discoverable from checked-in definitions. The manifest separately records 1,552 HubSpot reference-only schemas that cannot resolve because their local component targets are absent; those fail before field enumeration and are not included in the 125 open-object count.

The recurring failure pattern is **declarative-marker execution drift**: a guard trusts optional metadata instead of the code path that actually owns dispatch. Request-contract enforcement therefore takes effective runtime ownership as its source of truth.

The cross-layer failure class is **correct at authoring but wrong at runtime**. The lesson is **verify the fix where the action happens**: evidence collection alone is insufficient unless the authoring validator and command/write runtime consume the same decoded wire shape. The escaped-pointer, bracket-query, static-array, and deep-merge tests therefore exercise the acting layer as well as citation normalization.
